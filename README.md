# X-SCRM
### Explainable Supply Chain Risk Management

**An AI-assisted third-party cybersecurity risk assessment platform combining rule-based scoring, machine learning and explainable risk analysis.**

X-SCRM is an independent software development project exploring how artificial intelligence and data science can improve Third-Party Risk Management (TPRM).

The platform evaluates vendor risk profiles, classifies vendors into risk tiers and provides an interactive dashboard to support more structured and transparent cybersecurity risk assessments.

---

## 🎯 Project Objectives

- Assess cybersecurity risks associated with third-party vendors.
- Evaluate vendors across multiple risk dimensions.
- Classify vendors into Low, Medium and High risk categories.
- Apply machine learning to identify patterns in vendor risk profiles.
- Improve transparency through explainable risk scoring.
- Support risk-based decision-making through an interactive dashboard.

---

## 🚀 Core Features

### 1. Synthetic Vendor Dataset

X-SCRM currently uses a synthetic dataset containing **10,000 vendor records**.

Vendor attributes include:

- Industry and geographical region.
- Vendor criticality.
- Data sensitivity.
- API access level.
- Incident history and severity.
- Cybersecurity and business risk indicators.

Synthetic data allows the platform to be developed and tested without exposing real organisational or vendor information.

### 2. Rule-Based Risk Engine

The risk engine evaluates vendors across four dimensions, producing an overall score out of 100.

| Risk Category | Maximum Score |
|:---|---:|
| Cybersecurity | 40 |
| Compliance | 30 |
| Business Criticality | 20 |
| Incident History | 10 |
| **Total** | **100** |

**Risk Classification**

| Risk Score | Risk Tier |
|:---:|:---|
| 0–39 | 🟢 Low |
| 40–69 | 🟡 Medium |
| 70–100 | 🔴 High |

The engine also records component-level contributions, helping explain how individual risk factors influence the overall assessment.

### 3. Machine Learning Risk Classification

X-SCRM incorporates a **Random Forest classifier** to identify patterns in vendor risk profiles.

The machine learning pipeline includes:

- Data preprocessing and categorical encoding.
- Class imbalance handling.
- Model training and evaluation.
- Cross-validation.
- Risk classification.
- Validation-based classification threshold tuning.

Particular attention is given to identifying High-risk vendors because they represent a significantly smaller proportion of the dataset.

> **Model limitation:** The current model learns from risk tiers generated by the rule-based engine. It does not predict actual security breaches or independently validated real-world vendor incidents. Its outputs are decision-support recommendations, not definitive risk assessments.

### 4. Interactive Risk Dashboard

The Streamlit dashboard allows users to explore vendor assessments through:

- Vendor risk distribution visualisations.
- Risk-tier filtering.
- Individual vendor selection.
- Overall risk scores.
- Risk component breakdowns.
- Vendor-level assessment details.

## ⚙️ Installation and Setup

### Prerequisites

- Python 3.10 or later.
- Git.
- Visual Studio Code or another Python-compatible editor.

### 1. Clone the repository

```bash
git clone https://github.com/Tshepo97-codE/x-scrm.git
```

### 2. Navigate into the project

```bash
cd x-scrm
```

### 3. Create a virtual environment

```bash
python -m venv venv
```

### 4. Activate the virtual environment

**Windows CMD:**

```cmd
venv\Scripts\activate
```

**Windows PowerShell:**

```powershell
.\venv\Scripts\Activate.ps1
```

### 5. Install dependencies

```bash
pip install -r requirements.txt
```

### 6. Launch the dashboard

```bash
streamlit run dashboard/app.py
```

The dashboard should open automatically in your default browser.

## 🔬 Project Limitations

X-SCRM is an ongoing development project.

Current limitations include:

- The dataset is synthetic and does not represent actual vendor populations.
- Machine learning labels originate from the rule-based scoring engine.
- Performance on synthetic data does not establish real-world predictive accuracy.
- High-risk classification requires careful evaluation due to class imbalance.
- Model recommendations require human oversight.
- Explainability, API integration and analyst review functionality remain planned development areas.

These limitations are important when interpreting model performance and considering real-world applications.
